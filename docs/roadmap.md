## Next steps, in order

1. Linux and macOS hardware verification of the current engine, packages,
   tray, sign-in start and Linux virtual devices
   ([checklist](development/testing-linux-macos.md)).
2. Engine autostart per platform (Windows: per-user first, service mode
   with startup-sound timing test; Linux: systemd user unit; macOS:
   LaunchAgent).
3. ~~Linux virtual devices~~ (done, PipeWire stream nodes; needs a test on
   a desktop with audio hardware).
4. Per-application capture on Windows (WASAPI process loopback) as an
   input source. Virtual devices: soak test, reboot/sleep behaviour, own
   USB product id.
5. GUI: global hotkeys; verify the Linux tray on real desktops (KDE, GNOME
   with AppIndicator); verify the sign-in toggles of the Settings tab at an
   actual sign-in (Windows, Linux, macOS).
6. Native WASAPI backend for low latency.
7. macOS HAL plug-in ([ADR 0010](adr/0010-macos-virtual-devices.md): CI
   spike for ad-hoc signing first); Windows driver once signing is arranged.
8. Releases: sign feed manifests (minisign) and apply to SignPath for
   Authenticode; per-machine MSI once a service mode exists.

## Known limitations found in testing

* ~~**FIFO latency only ever grows.**~~ Fixed: writer block sizes use a
  30–60 s sliding maximum, and after 5 glitch-free minutes the target
  shrinks by 1 ms every 5 s (≈ 200 ppm correction) down to the configured
  target or the largest block requirement of the quiet period. A first
  hardware run exposed a shrink/raise oscillation on an output whose master
  occasionally delivers double periods; the quiet-period floor fixes it.
* **Drift ripple after re-priming.** The controller keeps its learned ratio
  but the fill jumps; transient corrections up to ~90 ppm were observed
  right after an underrun, settling within the loop time constant.
